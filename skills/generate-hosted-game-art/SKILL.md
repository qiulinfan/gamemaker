# Generate Hosted Game Art

Turn a hosted provider credential into (1) a verified capability map and (2)
budget-authorized base assets for the art pipeline. Hosted generation is the
preferred source for original base assets when credentials and budget exist;
Blender (via `$auto-ta`) is the downstream adaptation, audit, and lookdev
layer, not the primary authoring route.

Match user-facing explanations, prompts, and handoffs to the user's language
unless the user requests another language. Keep commands, identifiers,
structured keys/action codes, and raw errors unchanged.

## Keep the Boundaries Clear

- This Skill talks to hosted generation APIs only. Use `$search-game-art` to
  find and license existing assets, `$create-2d-game-art` for deterministic 2D
  production, `$auto-ta` for Blender-side authoring, adaptation, and the audit
  chain, and `$character-rig-animation-alignment` for humanoid retargeting.
- Supported providers: **meshy** and **tencent-cloud**. Refuse other provider
  types with `PROVIDER_UNSUPPORTED` instead of guessing an API shape.
- A successful provider response proves only that output was returned. Every
  generated asset keeps `validation_status: prototype` until the same geometry,
  material, rig, visual, export, and engine gates as locally authored assets
  pass through the `$auto-ta` audit chain. Never convert `prototype` into an
  accepted claim because a render looks right.

## Accept the Credential File

The user names the credential file path and the provider type. Do not scan
directories for keys, do not copy the file anywhere (including repositories,
receipts, and logs), and never echo the secret or place it in a URL. Reference
the file by absolute path at call time only.

Expected formats:

- meshy: a single `msy_...` key on one line.
- tencent-cloud: `SecretId:AKID...` and `SecretKey:...` lines (a Tencent Cloud
  API key pair, TC3-signed; this is not a TokenHub Bearer key).

If the file does not match the declared provider, stop with
`CREDENTIALS_INVALID` and show the expected format, not the file contents.

## Resolve the Bundled Client

Resolve the bundled client from the globally linked Skill, independent of the
target game's current directory. Probe the supported runtime Skill homes in
order — the Codex home first, then the Claude Code home — and use the first one
that actually contains the script. On macOS or Linux:

```sh
skill_dir=""
for candidate in \
    "${CODEX_HOME:-$HOME/.codex}/skills/generate-hosted-game-art" \
    "${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills/generate-hosted-game-art"; do
  if [ -f "$candidate/scripts/hosted_art_client.py" ]; then
    skill_dir="$(realpath "$candidate")"
    break
  fi
done
test -n "$skill_dir"
client="$skill_dir/scripts/hosted_art_client.py"
test -f "$client"
```

On Windows PowerShell 7:

```powershell
$CodexHome = if ([string]::IsNullOrWhiteSpace($env:CODEX_HOME)) {
  Join-Path ([Environment]::GetFolderPath('UserProfile')) '.codex'
} else {
  [System.IO.Path]::GetFullPath($env:CODEX_HOME)
}
$ClaudeHome = if ([string]::IsNullOrWhiteSpace($env:CLAUDE_CONFIG_DIR)) {
  Join-Path ([Environment]::GetFolderPath('UserProfile')) '.claude'
} else {
  [System.IO.Path]::GetFullPath($env:CLAUDE_CONFIG_DIR)
}
$SkillDir = @(
  (Join-Path $CodexHome 'skills\generate-hosted-game-art'),
  (Join-Path $ClaudeHome 'skills\generate-hosted-game-art')
) | Where-Object { Test-Path -LiteralPath (Join-Path $_ 'scripts\hosted_art_client.py') } |
  Select-Object -First 1 | ForEach-Object { (Resolve-Path -LiteralPath $_).Path }
if (-not $SkillDir) { throw 'GENERATE_HOSTED_GAME_ART_NOT_LINKED' }
$Client = (Resolve-Path -LiteralPath (Join-Path $SkillDir 'scripts\hosted_art_client.py')).Path
```

Treat failure to resolve from both runtime homes as
`GENERATE_HOSTED_GAME_ART_NOT_LINKED`; do not fall back to a `scripts/...`
path relative to the game repository. The client is standard-library Python
3.11+; no package installation is required.

## Probe First (free, mandatory before first generation)

Before the first generation with any key — and again after a long gap or a
reported plan change — run the free probe and present the capability map:

```sh
python3 "$client" probe --provider meshy --credentials /path/to/key.txt
python3 "$client" probe --provider tencent-cloud --credentials /path/to/keys.txt
```

The probe performs only free, read-only calls and can never bill:

- meshy: balance query plus a one-item GET on each capability family
  (text-to-3d, image-to-3d, multi-image-to-3d, retexture, remesh, rigging,
  animations, text-to-image). HTTP 200 = available to this key.
- tencent-cloud: account-balance query (also proves auth; a permission error
  here is non-fatal), a free `GetTokenCount`, and sentinel-id job queries for
  Hunyuan 3D standard/pro/rapid and Hunyuan image. `JobNotFound` means the
  service is activated and reachable; auth or not-activated errors are
  classified per capability.

Report to the user: remaining balance/quota, each capability's state, and the
Tencent settlement order caveat — free resource packs are consumed first, then
prepaid packs, and pay-as-you-go stays off by default, so a zero cash balance
with no claimed pack means generation calls will fail until the user claims the
free pack in the provider console. Do not claim a console action succeeded;
that step belongs to the user.

## Authorize Before Generating

Every generation batch needs the user's explicit authorization covering:
provider, model/endpoint, number of tasks, and a maximum budget in the
provider's unit (Meshy credits / Tencent points). State the cost anchors from
[references/provider-playbooks.md](references/provider-playbooks.md) before
asking — observed: Meshy preview 20 + refine 10 (+ remesh 5 + rigging 5 +
animation 3 per clip for characters), one successful Hunyuan 3D task 20 points
— treat these as estimates to verify against the account, not fixed prices.
Never submit during a probe, never exceed the authorized task count, and stop
the batch when the observed balance drop reaches the budget.

The client enforces the handshake: `submit` refuses to run without
`--acknowledge-billable`, and that flag may only be passed after the user
authorized the batch in this conversation.

## Run the Batch

For each authorized task:

```sh
python3 "$client" submit --provider meshy --endpoint text-to-3d \
  --credentials /path/to/key.txt --payload payload.json --acknowledge-billable
python3 "$client" status --provider meshy --endpoint text-to-3d \
  --credentials /path/to/key.txt --task-id <id>
python3 "$client" download --provider meshy --endpoint text-to-3d \
  --credentials /path/to/key.txt --task-id <id> --output-root /abs/output
```

Tencent uses `--action` instead of `--endpoint` (one of
`SubmitHunyuanTo3DJob`, `SubmitHunyuanTo3DProJob`, `SubmitHunyuanTo3DRapidJob`,
`SubmitHunyuanImageJob`); `status`/`download` derive the matching query action.

For characters (model + rig + animation) follow the task-id chain
`preview → refine → remesh → rigging → animations` and its failure modes in
[references/provider-playbooks.md](references/provider-playbooks.md) —
notably: negative-prompt away pedestals/busts, remesh to ≤320k faces before
rigging, and wait for each upstream task's SUCCEEDED before chaining.

Rules:

- Poll with `status` at a bounded cadence; do not create daemons or recurring
  automation.
- `download` writes only into a fresh `<provider>-<task-id>/` directory under
  an existing, explicit `--output-root`, hashes every artifact, and writes a
  `generation-receipt.json` with `validation_status: prototype`. Keep the
  output root outside any repository unless the user names a tracked location
  such as the project's `generated-assets/`.
- Record in the report: task ids, balance before/after when the provider
  exposes it, artifacts with hashes, and any task that failed or timed out.
  A failed or unfinished task is reported as such — never substitute prose for
  a missing artifact.
- Repository hygiene: raw downloads carry redundant giant formats (obj up to
  ~195 MB; GitHub rejects files over 100 MB). Version only the receipt and
  preview; the engine delivery is the optimized artifact inside the game
  project (see "Downstream optimization" in the provider playbook).

## Hand Off Downstream

Hosted output is source material, not a delivery:

- 3D artifacts go to `$auto-ta` (`adapt_asset` or `audit_or_handoff`) for the
  Blender-side audit chain, adjustment, and engine handoff; humanoids that need
  external animation continue to `$character-rig-animation-alignment`.
- Images used as sprites or UI go to `$create-2d-game-art` for deterministic
  production and its own receipt.
- Pass the generation receipt along; the downstream receipt references it as
  the provenance record. License and content-policy obligations of the
  provider's terms stay with the asset.
